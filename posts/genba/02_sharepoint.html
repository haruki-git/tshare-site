今回のテーマ

今回のテーマは、Microsoft SharePointです。

SharePointは、Microsoft 365で文書や情報を共有し、組織やチームのためのサイトを作る基盤です。利用者からは、社内ポータル、資料置き場、Teamsのファイル画面などとして見えることがあります。

ただし、SharePointを単なるクラウド上の共有フォルダーとして理解すると、権限、共有リンク、Teams、OneDrive同期との関係が分かりにくくなります。今回は、SharePointがシステム全体のどこにあり、どのように認証やファイル共有とつながるのかを整理します。

今回の目標：SharePointのサイト、文書ライブラリ、リスト、権限の役割を理解し、「開けない」「編集できない」「同期されない」「共有した相手が見られない」といった問い合わせを基本的な観点で切り分けられるようにします。

Microsoft SharePointとは

Microsoft SharePointは、組織やチームが情報を保存、整理、共有し、共同作業を行うための製品・サービスです。

Microsoft 365のクラウドサービスとして提供されるものは、公式資料ではSharePoint in Microsoft 365と表現されます。一般にはSharePoint Onlineと呼ばれることもあります。一方、組織内のサーバーへ構築するSharePoint Serverもあり、同じSharePointでも運用方式は異なります。

この記事では、主にMicrosoft 365上のSharePointを扱います。画面名称や利用できる機能は、契約プラン、組織の設定、更新時期、権限によって異なる場合があります。

SharePointでは、Webサイトのようなページを作るだけでなく、文書ライブラリにファイルを保存したり、リストに表形式の情報を登録したりできます。検索、バージョン履歴、共同編集、アクセス権の管理なども組み合わせて使います。

何のために使われるか

SharePointは、組織の情報を一か所へ集め、必要な人が必要な範囲で利用できるようにするために使われます。

主な用途 内容
文書共有 手順書、申請書、会議資料などを文書ライブラリで保存・共有する
共同作業 複数の利用者がOffice文書を共同編集し、更新履歴を管理する
社内ポータル お知らせ、規程、リンク、予定、部門情報などをページにまとめる
情報管理 問い合わせ、備品、課題、申請状況などをリストで管理する
検索 サイト、ページ、文書、リスト項目などから必要な情報を探す
アクセス制御 閲覧、編集、管理など、利用者ごとに可能な操作を制御する

ファイルサーバーでも文書は共有できますが、SharePointはページ、リスト、検索、バージョン履歴、共有リンク、Microsoft 365との連携を含む情報共有基盤です。フォルダー構造だけで整理するのではなく、列やビューを使って情報を分類することもできます。

システム全体のどこに存在するか

Microsoft 365上のSharePointは、利用者の端末からインターネット経由で接続するクラウドサービスです。利用者はブラウザー、Officeアプリ、Teams、OneDrive同期アプリなどからSharePoint上の情報へアクセスします。

認証には、Microsoft Entra IDを中心としたMicrosoft 365のID基盤が関係します。利用者がサインインした後、SharePointはサイトやファイルに対するアクセス権を確認します。

利用者
  ↓ サインイン
Microsoft Entra IDなどの認証基盤
  ↓ 認証結果
Microsoft 365のSharePoint
  ├─ サイト・ページ
  ├─ 文書ライブラリ・ファイル
  └─ リスト・リスト項目
  ↑
ブラウザー / Office / Teams / OneDrive同期アプリ

Microsoft Teamsのチャネルへアップロードしたファイルは、対応するチームのSharePointに保存されます。一方、Teamsの1対1チャットやグループチャットで共有したファイルは、送信者側のOneDriveに保存されるため、同じTeams上のファイルでも保存先が異なります。

したがって、Teamsでファイルが開けない問い合わせでも、実際に確認する対象はSharePointのサイト、文書ライブラリ、OneDrive、権限設定のいずれかである可能性があります。

SharePointを構成する基本要素

サイト

サイトは、ページ、ファイル、リスト、権限などをまとめる単位です。プロジェクト、部門、業務、全社ポータルなど、目的ごとに作成されます。

チームで共同作業をするためのチームサイトと、多くの利用者へ情報を発信するためのコミュニケーションサイトが代表的です。

ページ

ページは、ニュース、文章、リンク、画像、文書一覧などを配置して情報を見せる画面です。ページ自体にすべての情報を保存するのではなく、文書ライブラリやリストの内容を表示することもあります。

文書ライブラリ

文書ライブラリは、ファイルを保存・管理する場所です。ファイル名やフォルダーだけでなく、更新者、更新日時、分類などの列を持たせることができます。バージョン履歴、共同編集、共有、同期も文書ライブラリと関係します。

リスト

リストは、行と列で情報を管理する仕組みです。表計算ファイルに似ていますが、入力項目、表示方法、権限、通知、Power Automateなどとの連携を設定できます。

権限

権限は、誰が閲覧、編集、管理できるかを決める仕組みです。サイト全体の権限を引き継ぐ構成もあれば、特定のライブラリ、フォルダー、ファイルだけに個別の権限を設定する構成もあります。

代表的な役割として、所有者、メンバー、閲覧者があります。ただし、組織独自のグループや権限レベルが使われる場合もあるため、名称だけで操作範囲を断定しません。

基本的な仕組みと処理の流れ

利用者がSharePoint上のファイルを開く場合、認証、アクセス先の特定、権限確認、ファイル取得という流れで処理されます。

1. 利用者がサイトや共有リンクへアクセスする
        ↓
2. Microsoft 365のアカウントで認証する
        ↓
3. 対象テナント、サイト、ライブラリ、ファイルを特定する
        ↓
4. SharePointが利用者やグループの権限を確認する
        ↓
5. 許可された操作に応じて閲覧・編集・共有を行う
        ↓
6. 変更内容やバージョン履歴がクラウド側に保存される

共有リンクを使う場合も、リンクを知っているだけで必ず開けるとは限りません。リンクの種類、対象者、サインインしているアカウント、組織やサイトの外部共有設定などが関係します。

ファイルをOneDrive同期アプリで同期する場合、クラウド上の文書ライブラリと端末上の同期フォルダーが連携します。端末上で行った変更や削除がクラウド側にも反映されることがあるため、単なるバックアップ用コピーとは考えません。

利用者・端末・サーバー・ネットワークとの関係

利用者との関係

利用者は、ブラウザーやTeamsからサイトを開き、文書の閲覧、共同編集、共有、検索などを行います。同じ利用者でも、サインインしたアカウントや所属グループが違えば、表示される情報や操作できる範囲が変わります。

端末との関係

ブラウザーのサインイン状態、Officeアプリのアカウント、OneDrive同期アプリの状態、端末時刻、キャッシュなどが利用に影響する場合があります。ブラウザーでは開けるが同期フォルダーでは開けない場合、SharePointサービス全体ではなく同期アプリ側を中心に確認できます。

クラウドサービスとの関係

SharePointは、Microsoft Entra ID、Teams、OneDrive、Officeアプリ、Power AutomateなどのMicrosoft 365サービスと連携します。問い合わせを受けた画面と、実際にデータを保存しているサービスが同じとは限りません。

ネットワークとの関係

SharePointへのアクセスには、インターネット接続、名前解決、HTTPS通信、プロキシやファイアウォールの許可などが関係します。ブイ・ピー・エヌ経由時だけ開けない場合は、通信経路や組織のアクセス制御も確認します。

Microsoft 365の接続先や通信要件は変更される可能性があります。固定的なユーアールエルやIPアドレスを推測で登録せず、Microsoftの最新の公式資料と組織の設計を確認します。

実務のイメージ

一次対応者は、SharePointのサイト設計や権限設定を自分で変更しなくても、利用者から多くの問い合わせを受けます。

例えば、「昨日まで見られた資料が開けない」「共有リンクを送った相手がアクセス拒否になる」「Teamsのファイルが同期されない」「編集できるはずなのに読み取り専用になる」「削除したファイルを戻したい」といった問い合わせです。

このときは、SharePointが壊れていると決めつけず、利用者側、端末側、ネットワーク側、認証側、権限側、サービス側を分けて確認します。

  1. 一人だけか、同じサイトの複数利用者で発生しているか
  2. サイト全体が開けないのか、特定のファイルだけ開けないのか
  3. ブラウザー、Teams、Office、同期フォルダーのどこで発生するか
  4. 正しいMicrosoft 365アカウントと組織へサインインしているか
  5. 対象サイト、ライブラリ、フォルダー、ファイルの権限がどうなっているか
  6. 共有リンクの対象者と、実際にアクセスしているアカウントが一致するか
  7. Microsoft 365のサービス正常性に問題が出ていないか

一次対応では、利用者の画面だけでなく、対象のサイト名、ファイルの場所、ユーアールエル、発生時刻、エラー文、利用中のアプリを記録します。上位担当へ連携するときに、「SharePointが使えない」から一段具体的な情報へ変えることが重要です。

一般利用者・運用担当者・管理者の役割

役割 主な対応
一般利用者 正しいサイトとアカウントを使い、権限の範囲内で閲覧・編集・共有する。エラー内容と対象ファイルを伝える
運用担当者・一次対応者 影響範囲、アクセス経路、認証状態、対象URL、権限、同期状態、サービス正常性を確認して切り分ける
サイト所有者 サイト内のメンバー、ライブラリ、ページ、共有方法などを業務目的に合わせて管理する
Microsoft 365・SharePoint管理者 組織全体やサイト単位の設定、外部共有、アクセス制御、容量、監査、サービス障害への対応を行う

利用者へ閲覧権限を追加できるのが、必ずしもMicrosoft 365全体の管理者とは限りません。サイト所有者が対応する構成もあります。誰がどの範囲を管理しているかを整理しておくと、問い合わせの連携先を判断しやすくなります。

問い合わせ・障害時の切り分け

最初に記録する情報

  • 発生日時、利用者、影響を受けている人数
  • サイト名、ライブラリ名、フォルダー名、ファイル名
  • アクセスしたURLや共有リンク
  • 表示されたエラー文と画面
  • ブラウザー、Teams、Office、同期フォルダーのどこで発生したか
  • サインインしているアカウントと組織
  • 直前の権限変更、ファイル移動、名前変更、共有設定変更

利用者・認証側

正しいアカウントでサインインしているかを確認します。複数組織のゲストとして登録されている利用者や、個人用Microsoftアカウントも使っている利用者では、別のアカウントで開いていることがあります。

Microsoft 365のほかのサービスへサインインできるかも確認します。サインイン自体ができなければ、SharePointの権限より前に、アカウント、パスワード、多要素認証、条件付きアクセスなどの認証側を確認します。

権限・共有側

サイト全体が開けるか、ライブラリが開けるか、特定のフォルダーやファイルだけ開けないかを確認します。上位の権限を引き継いでいるか、個別の権限が設定されているかも重要です。

共有リンクでは、組織内のユーザー、特定のユーザー、リンクを知っているユーザーなど、選ばれた共有範囲を確認します。編集リンクと閲覧リンクも区別します。組織やサイトの設定によって、外部共有の選択肢が制限されることがあります。

ブラウザー・端末側

別ブラウザーやプライベートウィンドウで同じ問題が再現するかを確認すると、保存されたアカウント情報やキャッシュの影響を切り分けやすくなります。Officeアプリだけで失敗する場合は、Office側のサインインアカウントや更新状態も確認します。

同期側

ブラウザーで文書ライブラリを開けるかを先に確認します。ブラウザーでは正常で、端末の同期フォルダーだけに問題がある場合は、OneDrive同期アプリのサインイン状態、同期アイコン、エラー表示、対象ライブラリ、ファイル名やパスの制限を確認します。

同期エラーがあるからといって、すぐに同期解除やリセットを行うとは限りません。未同期の変更が残っていないかを確認し、組織の手順に従います。

ネットワーク側

インターネット接続、名前解決、HTTPS通信、プロキシ、ファイアウォール、ブイ・ピー・エヌを確認します。特定の拠点やネットワークだけで発生する場合は、通信経路や許可設定の可能性が高くなります。

サービス側

複数の利用者や複数サイトで同時に発生している場合は、Microsoft 365管理センターのサービス正常性を確認します。障害情報が出ていない場合でも、発生時刻、対象地域、対象機能を整理して管理者へ連携します。

削除・変更・検索の問題

ファイルが見つからない場合は、削除だけでなく、移動、名前変更、表示ビューのフィルター、権限変更も確認します。削除されたファイルは、ごみ箱やバージョン履歴から復元できる場合があります。

検索結果にすぐ表示されない場合は、検索インデックスへ反映されるまでの時間や、利用者の権限も関係します。検索に出ないことと、ファイル自体が存在しないことは分けて考えます。

切り分けの基本：「SharePointが開かない」ではなく、「サイトには入れるが特定ファイルだけアクセス拒否」「ブラウザーでは開けるがOneDrive同期だけ停止」のように、正常な範囲と異常な範囲を言葉にします。

よくある勘違い

SharePointは、クラウド上の共有フォルダーである

ファイル共有は主要な機能ですが、サイト、ページ、リスト、検索、権限、バージョン管理などを含む情報共有基盤です。

Teamsにあるファイルは、Teamsだけに保存されている

Teamsのチャネルファイルは、対応するSharePointサイトに保存されます。チャットで共有したファイルはOneDriveに保存されるため、保存場所を区別します。

OneDriveとSharePointは同じものである

どちらもMicrosoft 365のファイル機能と深く関係しますが、OneDriveは主に個人を起点としたファイル領域、SharePointは主にチームや組織を起点とした情報共有基盤です。

共有リンクを送れば、相手は必ず開ける

リンクの対象者、相手のアカウント、外部共有設定、サイトやファイルの権限によっては開けません。どのアカウントで開くリンクかを確認します。

サイトが開けるなら、すべてのファイルを編集できる

サイト、ライブラリ、フォルダー、ファイルで権限が異なる場合があります。また、閲覧権限はあっても編集権限がないことがあります。

同期フォルダーのファイルは、クラウドとは別のコピーである

OneDrive同期アプリで同期している場合、変更や削除がクラウド側へ反映されることがあります。通常のローカルバックアップと同じ感覚で扱わないようにします。

アクセス拒否は、ネットワーク障害である

ネットワーク障害でもアクセスできなくなりますが、アクセス拒否は、誤ったアカウントや権限不足によって表示されることも多くあります。エラー文と到達できている範囲を確認します。

Microsoft Teams チャネルのファイル保存先としてSharePointを利用する

要約

  • SharePointは、文書や情報を保存・整理・共有し、共同作業を行うための製品・サービスです。
  • 主な構成要素は、サイト、ページ、文書ライブラリ、リスト、権限です。
  • Microsoft 365上では、Microsoft Entra IDの認証やグループと連携してアクセスを制御します。
  • TeamsのチャネルファイルはSharePoint、チャットで共有したファイルは主にOneDriveへ保存されます。
  • SharePointライブラリの端末同期には、OneDrive同期アプリを使用します。
  • 障害時は、利用者、端末、ネットワーク、認証、権限、サービスを分けて確認します。
  • サイト全体、ライブラリ、フォルダー、ファイルのどこまで開けるかを確認します。
  • 一次対応では、URL、アカウント、エラー文、アクセス経路、影響範囲、直前の変更を記録します。
